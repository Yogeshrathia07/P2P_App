How it works

Four steps. No server in the middle.

  1. 1

    Create a room

    Pick a room name. VYBE makes an invite: a QR code and a link.

  2. 2

    Friend opens it

    They scan the QR or tap the link. Their browser prepares a reply by itself.

  3. 3

    Send the reply back

    Scan or paste their reply on your screen. It connects the moment you do.

  4. 4

    Study together

    A direct WebRTC channel opens and your chat flows between your two browsers.

What you get

  • Real peer-to-peer

    Messages go through an RTCDataChannel straight to your peer.

  • Saved on your device

    Your chat survives a refresh, stored only in your own browser.

  • No duplicates, right order

    Unique IDs and sequence numbers keep every chat tidy.

  • Safe input

    Every payload from a peer is checked, and shown as plain text only.

  • History sync

    When you reconnect, you and your peer swap the messages you each hold.

  • No sign-up

    No account, no database, no message server. It is a static website.

    About

    About VYBE

    What is VYBE?

    VYBE is a small study room for two students. You create a room, share two short codes, and your browsers talk to each other directly. It is a college project built with plain HTML, CSS and JavaScript, and it runs as a static website on GitHub Pages.

    What is peer-to-peer communication?

    In a normal chat app, every message goes to a company's server first and is then forwarded to the other person. In peer-to-peer communication the two devices (the peers) send data straight to each other. There is no server in the middle holding your messages.

    Why WebRTC?

    WebRTC is built into modern browsers. It lets two browsers set up a direct connection, and its RTCDataChannel sends text or data between them. We need no plug-in and no backend for the messages themselves.

    How does it work without a message server?

    Two browsers must first learn how to reach each other. Normally a signalling server passes that information along. VYBE replaces it with you: you share an invite (link or QR) and they send back a reply code. After that, the channel opens and messages never touch a server. A public STUN helper is used only to discover each device's public address. If a relay (TURN) server is set up, it is used only when a direct connection is impossible.

    What it cannot do

    • It does not work on every network. Strict firewalls need a relay (TURN) server, which only works if the developer has added one. See the README.
    • Only people who are online at the same time can chat. If your peer is offline, nobody can send you their history.
    • Your chat lives in your browser storage. Clearing site data deletes it.
    • Names are not verified. Anyone can type any name.
